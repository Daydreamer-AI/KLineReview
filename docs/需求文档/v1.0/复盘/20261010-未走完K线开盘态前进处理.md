## 1. 背景与目标

- 背景：
  - 复盘前进落地时直接显示“下一根完整 K 线”，用户看不到该 K 线刚开盘时的形态，无法在“已知开盘价、未知当根走势”的位置做决策。
  - 需要与既有 `cfg.ctfEnabled`（未走完 K 线补全后是否自动前进）区分并共存：两者都描述“未走完 K 线的前进”，但目标相反——ctfEnabled 让每根 K 线**一拍**走完，openFirst 要求每根 K 线**两拍**（开盘态 → 完整态）。
- 目标：
  - 新增 `cfg.openFirst`（默认 False）：手动单步前进落地时先显示下一根的开盘态（属于未走完），再次点击前进才补全为完整 K 线。
  - 明确两个开关的优先级：**openFirst 优先**——openFirst 开启时抑制 ctfEnabled 的“补全并自动前进”。

## 2. 需求描述（功能点）

- [x] 配置项（`src/common/config.py`）：`openFirst = ConfigItem("Review", "openFirst", False, BoolValidator())`，持久化于 `app/config/config.json` 的 `Review.openFirst`。
- [x] 设置页（`review_setting_interface.py`）：Operation 分组新增 `Open first` 开关卡片；`openFirst` 开启时置灰“Complete the forward”（ctfEnabled）卡片，提示自动前进被抑制。
- [x] 开盘态落地（`indicators_view_widget.step_forward`）：
  - 仅**手动单步前进**（`steps == 1`）且 `cfg.openFirst=True` 时落地开盘态；
  - “前进 N 步”（`cfg.fastForwardStep`，3~10）、自动播放（`slot_animation_step` 传 `open_first=False`）、滑块拖动、回到最前/最后、新加载、周期切换均不引入开盘态。
- [x] 开盘态形态（`_apply_open_first_bar`，显示层变换，不改基周期数据）：
  - `open` 取该 bar 真实开盘价，`high/low/close` 与 `open` 一致（刚开盘，无涨跌区间）；
  - `volume/amount/turnover_rate` 置 0，`is_complete=False`（属于未走完状态，可被补全）；
  - 时间标签取**周期开始时刻**：日线及以上为周期开始日（周=周一、月=1 日）09:30，分钟级为槽位开始时刻；
  - 按变换后的数据重算指标（trailing 指标只依赖历史与当前 bar，无未来数据）。
- [x] 再次前进补全：复用既有 `_complete_unfinished_current_bar`，把开盘态视为未走完，按周期内最后一根基周期 bar 时刻重建为完整 K 线，复盘位置不动。
- [x] 读取一致性（`get_current_kline_data`）：改为返回当前显示数据（含开盘态），与 `get_kline_price_by_index`/`get_current_date_time_by_index` 一致，保证模拟交易价格、时间与图表显示相同。
- [x] 状态清理：回退、回到最前/最后、滑块跳转、加载新数据、周期切换（`init_animation`）时清除开盘态，开盘态不会残留。

## 3. 验收标准

- [x] `openFirst=True`、周五复盘看周线（当前周完整）：单步前进落地为下一周开盘态（索引 +1、`is_complete=False`、`high=low=close=open`、`volume=0`、时间标签为下一周周一 09:30）；
- [x] 再次单步前进：补全为完整周（索引不变、时间标签为当周最后交易日 15:00、收盘价为周五收盘价）；
- [x] `openFirst=True` + `ctfEnabled=True`：进行中 K 线上点击前进只补全、不自动前进（openFirst 优先）；
- [x] “前进 N 步”与自动播放落地均为完整 K 线，不出现开盘态；
- [x] 开盘态下回退/滑块/切周期后不残留开盘态；
- [x] 开盘态只影响显示数据，`dict_stock_data` 中的周期数据仍为完整 bar；
- [x] 日线 + 5 分钟基周期（分钟级链路）下同样成立：落地标签 09:30、补全后 15:00；
- [x] `python -m unittest discover -s tests -v` 全绿（新增 `TestForwardOpenFirst` 6 项）。

## 4. 影响范围

- 涉及模块/文件：
  - `src/gui/qt_widgets/MComponents/indicators/indicators_view_widget.py`（开盘态显示层变换、前进分支、状态清理、`get_current_kline_data`）
  - `src/gui/qt_widgets/setting/review_setting_interface.py`（开关卡片与优先级提示）
  - `src/common/config.py`（配置项）
  - `tests/test_review_period_switch.py`（`TestForwardOpenFirst`）
- 涉及数据/数据库：无 schema 变更；配置新增 `Review.openFirst`（缺省 False，兼容旧配置文件）。
- 兼容性与风险：
  - 默认 False，行为与改动前完全一致；“前进 N 步”与自动播放不受影响。
  - 开盘态为显示层状态（不写入 `dict_stock_data`/`_base_stock_data`），任何重新聚合都不会污染周期数据；但状态只保留在**当前停留位置**，切周期后该 bar 按完整 K 线呈现。
  - 模拟交易：开盘态下 `low=high=open`，买入挂单在“价格 ≥ 开盘价”时即按开盘价成交（等价于“开盘价成交”），成交时间取周期开始时刻；这是预期语义变化，需在冒烟时确认。
  - 跨周期切换：开盘态时间标签为周期开始时刻，切到更小周期时锚定该周期开始日（日线按完整日呈现，沿用 `_build_partial_day_df` 既有回退行为）。
