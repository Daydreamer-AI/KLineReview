# 数据源适配接入设计（为多数据源/1 分钟级预留）

> 目标：在不改动复盘周期聚合、锚定、进行中/自动走完逻辑的前提下，接入新的行情数据源
> （AKShare、TuShare、券商接口等），尤其是 Baostock 不提供的 **1 分钟** 数据。
> 本文是“扩展设计”，当前代码只有 Baostock 一个源；落地时按此实现。

## 1. 现状与扩展点

复盘数据链路的**唯一外部依赖**是“基周期拉取”：

```text
BaostockDataFetchTask（远程基周期）
   └─ process_daily_stock_data / process_minute_level_stock_data
        └─ 返回统一 DataFrame（date/time/OHLCV/...）
             └─ 注入 ReviewWidget._BASE_LOAD_PERIODS（日线、5 分钟）
                  └─ period_aggregator 本地聚合出全部上级周期
```

因此接入新数据源只需满足两件事：

1. **返回统一格式的基周期 DataFrame**（见第 2 节）；
2. **在拉取任务里把“周期 → 数据源函数”的分发补上**（见第 3 节）。

聚合器、锚定、进行中/自动走完、时间传播**完全复用，不需要改**。

## 2. 基周期 DataFrame 统一格式

无论来自哪个数据源，基周期 DataFrame 必须包含以下列：

| 列 | 类型/格式 | 说明 |
| --- | --- | --- |
| `date` | `YYYY-MM-DD`（字符串或可被 `pd.to_datetime` 解析） | 交易日 |
| `time`（分钟级） | `YYYY-MM-DD HH:MM:SS` 或 baostock 紧凑格式 | 分钟 bar 结束时刻；日线级可无 |
| `code` / `name` | 字符串 | 个股标识与名称（名称由任务层补齐） |
| `open/high/low/close` | 数值 | OHLC |
| `volume` / `amount` | 数值 | 成交量 / 成交额 |
| `adjustflag` | 数值 | 复权方式（前复权 2） |

建议复用 `BaostockDataManager.data_type_conversion` 做统一的类型转换
（date→date、time→Timestamp、数值列→numeric）。

### 一致性要求

- **时间标注**：分钟 bar 一律以“结束时刻”标注（与 baostock 一致），聚合器按
  `结束时刻 - 周期时长` 反推槽位归属；
- **复权**：基周期统一前复权（`adjustflag=2`），聚合后仍为前复权；
- **排序**：按 date(+time) 升序返回。

## 3. 接入步骤（以 1 分钟源为例）

### 3.1 新增数据源适配函数

在 `src/processor/` 下新增（或扩展）适配器，例如
`ak_stock_data_processor.py` / `broker_data_processor.py`：

```python
def process_1m_stock_data(self, code, start_date=None, end_date=None, adjustflag='2'):
    """返回统一格式的 1 分钟 DataFrame（列见第 2 节）。"""
    ...
```

### 3.2 分发：BaostockDataFetchTask.execute

在分钟级分支按周期分发：

```python
if self.period == TimePeriod.MINUTE_1:
    df_data = AKStockDataProcessor().process_1m_stock_data(
        self.code, self.start_date, self.end_date, self.adjustflag)
elif TimePeriod.is_minute_level(self.period):
    df_data = BaoStockProcessor().process_minute_level_stock_data(...)
```

（建议把“周期 → 取数函数”收敛为一张注册表，见第 5 节。）

### 3.3 基周期配置

`review_widget._BASE_LOAD_PERIODS` 加入 `TimePeriod.MINUTE_1`（可保留 5 分钟作为回退基周期）。

`_refresh_derived_period_data` 已按“最细已注入分钟基周期”自动选择：

```python
minute_bases = [p for p in dict_stock_data if is_minute(p) and p < period]
base_period = min(minute_bases)   # 1m 注入后，10/15/30/... 自动以 1m 为基
```

### 3.4 拉取范围

1 分钟数据量是 5 分钟的 5 倍。`review_widget._get_fetch_start_date` 的分钟分支
（当前复盘日 - 30 天）需按数据源能力收紧（如 - 7 天），或由数据源返回空时自动回退。

## 4. 多数据源并存策略（建议）

### 4.1 基周期选择

- 同一周期多个源：优先取**最细可用**（1m > 5m）；
- 拉取失败回退：1m 失败 → 5m 成功 → 只注入 5m，10m 及以上仍由 5m 聚合；
- 用“源优先级表”配置，避免硬编码判断：

```python
MINUTE_BASE_PRIORITY = [TimePeriod.MINUTE_1, TimePeriod.MINUTE_5]
```

### 4.2 数据源注册表（建议）

```python
PERIOD_FETCHERS = {
    TimePeriod.DAY:      ("baostock", "process_daily_stock_data"),
    TimePeriod.MINUTE_1: ("akshare",  "process_1m_stock_data"),
    TimePeriod.MINUTE_5: ("baostock", "process_minute_level_stock_data"),
}
```

任务层按注册表分发，新增源 = 新增一行 + 实现取数函数，不动复盘链路。

## 5. 错误处理与限流

- baostock 为全局单会话，多个基周期必须**串行**（当前链式提交已满足）；
- akshare/券商接口通常有频控：拉取任务内加退避重试（指数退避 3 次）；
- 某源失败：记录日志、该基周期不注入，其余基周期正常出图；
- 空数据：视为“数据未覆盖”，由复盘切换/加载的现有回退逻辑兜底。

## 6. 验收建议

1. 1m → 5m → 10m → … → 120m 聚合槽数与 OHLCV 正确（复用 `tests/test_period_aggregator.py` 思路）；
2. 切换矩阵、盘中边界、进行中/自动走完、时间跨周期传播全部通过
   （复用 `tests/test_review_period_switch.py`）；
3. 1m 拉取失败时自动回退 5m 基周期，复盘不中断；
4. 运行 `python -m unittest discover -s tests -v` 全绿。
