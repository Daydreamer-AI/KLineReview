# 复盘周期聚合：维护与扩展指南

> 本文面向后续维护/扩展本功能的开发者，说明“改什么、改哪里、怎么验证”。
> 实现原理见《复盘周期切换与聚合设计.md》；需求背景见
> `docs/需求文档/v1.0/复盘/` 下两份 20260825 需求文档。

## 1. 核心约束（改之前先记住）

1. **远程只拉基周期**：默认 `[日线, 5分钟]`（`review_widget._BASE_LOAD_PERIODS`）。
   上级周期一律本地聚合，不要为了“拿到原生周线/月线”把远程上级周期加回拉取链。
2. **切换前必须重建目标周期**：`indicators_view_widget._refresh_derived_period_data`
   会在切换时按当前 as_of 重建目标周期。若跳过这一步直接用缓存，会出现
   “未走完显示成完整”“位置漂移”等回归。
3. **重建不能污染基周期**：视图保存注入时的原始基周期（`_base_stock_data`）。
   任何“进行中 bar 重建”（`_build_partial_day_df`、`aggregate_period`）只改展示副本，
   周/月聚合与重复加载都以原始基周期为准。
4. **周期内前进要自动补全**：`update_chart` 前调用
   `_sync_partial_bar_for_position`。新增“前进/跳转”类入口时，若走 `update_chart`
   则自动生效；若绕过，需自行处理进行中 bar 的补全。
5. **日线及以上没有 time 字段，切分钟要兜底**：非分钟来源切分钟级时
   `init_animation` 以当日 15:00 定位；分钟/日/周/月都带 `time` 后，才用精确时间跨周期传播。
6. **分钟 bar 区间是 `[start, end)`**：as_of 恰为某根 bar 起始时刻时归属上一根
   （`_get_anchor_matching_indices` 用 `槽位开始 < as_of`）。
7. **`.ui` 与 `.py` 必须同步**：周期按钮控件在
   `IndicatorsViewWidget.ui` 定义，`init_ui` 里接线；只改一边运行时会报“找不到控件”。
8. **Baostock 单会话不可并发**：多个基周期任务必须串行（现按顺序链式提交）。

## 2. 新增一个周期（数据层/界面层）

以“新增 17 分钟”为例：

1. `src/manager/period_manager.py`：
   - 增加枚举成员 `MINUTE_17 = '17m'`；
   - `get_chinese_label` 加 `cls.MINUTE_17: "17分"`；
   - `from_label` 加 `"17分": cls.MINUTE_17`；
   - `get_number_label` / `from_minute_number_label` 加 `"17"`；
   - `is_minute_level` 列表加入 `cls.MINUTE_17`；
   - `_period_order`（类属性 + `compare_to` 内）按大小插入。
2. `src/processor/period_aggregator.py`：**无需改动**（按 `period_start_key`
   通用切槽；非 5 倍数也支持，尾段不足一个周期）。
3. 界面展示（按需）：
   - `IndicatorsViewWidget.ui` 增加按钮 `btn_17m`（文本“17分”）；
   - `indicators_view_widget.init_ui` 接线 `addButton(self.btn_17m, id)`；
   - `review_widget._DEFAULT_LOAD_PERIODS` 加入 `TimePeriod.MINUTE_17`。
4. 验证：跑 `tests/test_period_aggregator.py` 看槽数是否符合预期，再在复盘页手动切换。

> 2/3 日线、2 周线、2/3/6/12 月线、7/25 分钟等枚举成员已存在，重复步骤 3 即可上界面。

## 3. 接入新数据源（如 1 分钟：AKShare/TuShare/券商）

当前链路只依赖“能提供指定周期 OHLCV 的基周期”。接入 1 分钟数据源：

1. 新增/复用 `src/processor/` 下的数据源适配函数，返回与 baostock 分钟数据一致的
   DataFrame：`date`（`YYYY-MM-DD`）、`time`（`YYYY-MM-DD HH:MM:SS` 或可被
   `BaostockDataManager.data_type_conversion` 解析的格式）、
   `open/high/low/close/volume/amount`、`adjustflag`。
2. `src/thread/baostock_data_fetch_task.py`：`BaostockDataFetchTask2.execute`
   增加/替换分钟基周期分支（`TimePeriod.MINUTE_1` → 新数据源函数）。
3. `review_widget._BASE_LOAD_PERIODS` 把 `MINUTE_5` 换成 `MINUTE_1`（或两者并存，
   取最细可用者）；`_refresh_derived_period_data` 已按“最细分钟基周期”自动选择。
4. 验证：聚合 1m→5m→10m…→120m 槽数与 OHLCV 一致；切换锚定正常。

> 注意：1 分钟数据量是 5 分钟的 5 倍，拉取范围（`_get_fetch_start_date` 分钟分支）
> 需按数据源能力调整（如只保留近 30 天）。

## 4. 修改交易时段切槽规则

槽位规则集中在 `period_aggregator._A_SHARE_SESSIONS`（09:30-11:30、13:00-15:00）与
`minute_slot_bounds`。若遇特殊交易时段（如半日市、节假日尾盘）：

- 半日市/尾盘缩短：`minute_slot_bounds` 已允许最后一槽不足 N，无需改动；
- 变更时段本身：改 `_A_SHARE_SESSIONS` 即可（`get_minute_slot_intervals` 与锚定共用）。

## 5. 复盘数据源改为本地库（可选）

若后续复盘改读本地 SQLite（`data/database/stocks/db/baostock`）：

- 基周期来源从“远程任务”换成 `BaostockDataManager.get_stock_data_from_db_by_period`；
- 聚合/锚定/进行中逻辑完全复用；
- 注意本地 `stock_data_1w` 表存在“周中残留 bar”历史问题（`update_weekly_stock_data`
  注释已说明），走本地路径后周线表不再参与复盘，问题自然规避。

## 6. 测试维护

- 运行全部测试（项目根目录）：

  ```bash
  python -m unittest discover -s tests -v
  ```

- 纯聚合测试 `tests/test_period_aggregator.py`：不依赖 GUI/网络，改聚合器必跑；
- 切换集成测试 `tests/test_review_period_switch.py`：离屏（offscreen）实例化复盘页，
  用合成数据覆盖“加载/矩阵/边界/进行中/自动走完/未覆盖回退”，改切换逻辑必跑；
- 新增场景的写法：在测试里用“合成日线 + 合成 5 分钟”构造数据，再模拟
  `_on_all_periods_loaded` → `slot_period_button_clicked`（或等价直接调用），
  断言锚点位置 / `is_complete` / OHLCV。
