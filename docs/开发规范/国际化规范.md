# 源码层规范

## 源语言统一用英文

所有 tr() / translate() 的 source text 必须是英文（或项目约定的源语言）；
❌ self.tr("登录") —— 后续翻英/日极其别扭；
✅ self.tr("Login")；

## 只用 tr() 包“用户可见文本”

需要翻译的：
窗口标题、菜单、按钮、标签、 tooltip、状态栏、MessageBox 正文；
.ui 文件里在 Designer 中输入的文本（由 uic/pyuic 自动走 tr）；

不需要翻译的：
变量名、日志 tag、文件路径、协议字段、内部 JSON key；
代码注释；

## tr() vs QCoreApplication.translate()

简单 Widget 内部可用 self.tr()；
跨类复用字符串、全局函数、非 QObject 类 → 必须用 QCoreApplication.translate("ExplicitContext", "text")；
Context 命名用类名或模块名，稳定、可读；

## .ui 文件规范

Designer 里直接写英文原文。

## 占位符与复数


| 场景    | 推荐方式      | 示例                                        |
| ----- | --------- | ----------------------------------------- |
| 简单变量  | `%s`      | `self.tr("Total: %s") % value`            |
| 多参数   | `{0} {1}` | `self.tr("From {0} to {1}").format(a, b)` |
| 复数    | `%n`      | `self.tr("%n items", "", count)`          |
| 格式化数字 | 先格式化再占位   | `QLocale().toString(n, 'f', 2)`           |
| 动态菜单  | 整句翻译      | `self.tr("Open %s") % ext`                |
| 复杂语序  | 整句+命名占位   | `self.tr("Delete {n} from {p}")`          |


# 项目国际化文档规范
当前项目国际化相关文件均放在./src/resources/i18n目录下，目前只提供英文、简体中文、繁体中文（未翻译）三个语言版本。
当规划版本所有开发完成后，再统一进行翻译，由./src/resources/update_i18n.py脚本完成。

# 国际化流程
1. 开发时遵循上面的源码层规范。
2. 封版后统一生成新的翻译文件，运行脚本：./src/resources/update_i18n.py。
3. 生成的翻译文件放在./src/resources/i18n目录下。
4. 翻译人员翻译.ts文件，翻译完成后记得release覆盖掉旧的.qm文件。
5. 更新翻译文件后，运行GUI测试，确保所有翻译正常。
6. 测试通过后，将新的翻译文件提交保存。
